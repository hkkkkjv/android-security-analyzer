# Сравнение с LLM

Для оценки эффективности разработанного инструмента было проведено сравнительное тестирование с языковой моделью ChatGPT-4o на тестовом проекте TestApp (демонстрационное Android-приложение с намеренно внедрёнными уязвимостями сетевой безопасности).

## Количественные результаты

| Показатель | Единица измерения | Наш инструмент | ChatGPT-4o |
|:---|:---|:---:|:---:|
| Всего обнаруженных уязвимостей | шт. | **34** | 21 |
| Уязвимости уровня CRITICAL | шт. | 6 | 4 |
| Уязвимости уровня HIGH | шт. | 11 | 11 |
| Уязвимости уровня MEDIUM | шт. | 15 | 6 |
| Уязвимости уровня LOW | шт. | 2 | 0 |
| Уникальных правил детекции | шт. | 15 | ~8 |
| Время анализа проекта | мс | **13** | 30 000 – 60 000 |
| Проанализированных файлов | шт. | 12 | 6 |

## Качественное сравнение

| Критерий | Наш инструмент + плагин | ChatGPT-4o |
|:---|:---|:---|
| Точность локализации | Точная строка + PSI-элемент в IDE | Номер строки в тексте (иногда неточно) |
| Автоматическое исправление | 6 Quick Fix по Alt+Enter | Только текстовое описание |
| Интеграция в IDE | Inline-подсветка, tooltip, real-time | Отсутствует |
| Скорость | <1 мс на файл | 5–30 секунд на файл |
| Детерминированность | Одинаковый результат | Результаты варьируются |
| Offline-работа | Не требует интернета | Требует API-ключ |
| CI/CD интеграция | JSON + exit-коды | Сложно автоматизировать |
| Полнота анализа Android-конфигов | network_security_config.xml, manifest, strings.xml | Частично |
| Контекстный анализ кода | По формальным правилам | Глубокий семантический анализ |

## Ключевые выводы

**Где наш инструмент превосходит LLM:**

- **На 62% больше уязвимостей** — 34 против 21. Преимущественно за счёт специализированных правил для Android-конфигураций (`network_security_config.xml`, `AndroidManifest.xml`, `strings.xml`), которые LLM анализирует поверхностно.
- **В 2300+ раз быстрее** — 13 мс против 30–60 секунд. Обеспечивает возможность интеграции в CI/CD и real-time анализ в IDE.
- **Автоматическое исправление** — плагин предлагает 6 Quick Fix (`ReplaceHttpWithHttpsFix`, `DisableCleartextFix`, `AddCertificatePinningFix`, `FixTrustManagerMethodFix`, `FixHostnameVerifierFix`, `ChangeUserCertsToSystemFix`), которые исправляют уязвимость одним нажатием Alt+Enter. LLM даёт только текстовые рекомендации.
- **Интеграция в рабочий процесс** — inline-подсветка в IDE с цветовой градацией по severity, tooltip с CVSS-оценкой, real-time анализ при редактировании кода.
- **Детерминированность и автономность** — одинаковый результат при каждом запуске, работа без интернета и API-ключей.

**Где LLM превосходит наш инструмент:**

- **Контекстный анализ кода** — LLM выявил 3 уязвимости, которые наш инструмент не обнаружил: небезопасная инициализация `sslContext.init(null, null, null)`, пустая реализация `getAcceptedIssuers()` и отсутствие backup pin в `CertificatePinner`. Эти проблемы требуют глубокого семантического понимания кода и запланированы к реализации в следующей версии.
- **Качество объяснений** — LLM предоставляет развёрнутые описания рисков и сценариев атак, тогда как наш инструмент даёт краткие рекомендации.

## Итог

Разработанный инструмент **оптимален для непрерывного мониторинга** и **автоматического исправления** уязвимостей в процессе разработки благодаря интеграции в IDE и системе Quick Fix. LLM эффективен для **глубокого разового аудита** сложных случаев. Оптимальный подход — комбинированное использование: специализированный инструмент для ежедневной работы, LLM — для экспертного анализа.
